# VideoLoader

Расширение для Chromium-браузеров (Chrome, Edge, Opera, Яндекс, версия 116+), которое
скачивает видео, открытое на текущей странице. Подходит для любого сайта, где плеер
отдаёт HLS-поток (`.m3u8`), DASH (`.mpd`) или обычный видеофайл (`.mp4`, `.webm`…).

Загрузчик HLS, разбор плейлистов, перепаковка TS → MP4 и исправление длительности
взяты из соседнего AnimeLoader.

## Установка

1. Откройте `chrome://extensions` (в Edge — `edge://extensions`).
2. Включите «Режим разработчика».
3. «Загрузить распакованное расширение» → выберите папку `videoloader`.

## Как пользоваться

1. Откройте страницу с видео и запустите воспроизведение. На значке появится число
   найденных потоков.
2. Нажмите на значок: во всплывающей панели будут видео этой страницы с длительностью,
   для HLS и DASH можно выбрать качество.
3. «Скачать». Панель можно закрыть: загрузка идёт в фоне, файл появится в
   `Загрузки/VideoLoader` под названием вкладки, например `Название серии [1080p].mp4`.
   Если такой файл уже есть, новый получит имя `… (1).mp4`.

Истории в панели нет: там видны только текущие загрузки. Готовая карточка пропадает
через несколько секунд, а ошибка остаётся, пока её не уберут кнопкой «Убрать».
Скачанные файлы — в папке («Открыть папку»).

**Папка.** Видео всегда сохраняются в подпапку `VideoLoader` папки загрузок браузера:
разрешений не нужно, после перезапуска ничего не сбрасывается. Кнопка «Открыть папку»
внизу панели открывает её (точнее, показывает в ней последнее скачанное видео: открыть
произвольную папку downloads API не умеет; если видео ещё нет, откроются «Загрузки»).
Чтобы видео попадали на другой диск, смените папку загрузок в `chrome://settings/downloads`
— подпапка `VideoLoader` появится там.

Если список пуст, а видео играет, обновите страницу: расширение видит только запросы,
сделанные после его установки.

## Как это устроено

- **Поиск видео.** `background.js` смотрит запросы вкладок (`webRequest`) и отбирает
  HLS-плейлисты, DASH-манифесты и видеофайлы больше 1 МБ (`js/sniffer.js`). Вместе с
  адресом запоминаются `Referer` и `Origin`, с которыми их запросил плеер. Куски файлов,
  запрошенные через адрес (`…&bytes=6463-1793194`, так качает плеер VK/Одноклассников),
  и рекламные ролики известных сетей (Яндекс, Adfox, Sizmek и др.) в список не попадают.
- **Заголовки.** Многие CDN без правильного `Referer`/`Origin` отвечают 403. Фон ставит
  сессионные правила `declarativeNetRequest`, которые подставляют те же заголовки,
  но только в запросы самого расширения: обычный просмотр сайтов они не затрагивают.
  Для доменов сегментов и вариантов качества ставятся такие же правила.
- **Попап** (`popup.html`, `js/popup.js`) читает найденные плейлисты и манифесты: показывает
  длительность и качества, скрывает варианты мастер-плейлиста, которые плеер тоже
  запросил, и сразу отсеивает неподдерживаемое (трансляции, отдельная аудиодорожка,
  шифрование кроме AES-128, DRM).
- **Загрузка** идёт в offscreen-документе (`offscreen.html`, `js/offscreen.js`), который
  не зависит от попапа. Файл пишется во временную папку OPFS, затем фон сохраняет его
  в `Загрузки/VideoLoader` через `downloads` API, и временный файл удаляется.
- **Формат.** fMP4-потоки склеиваются как есть, MPEG-TS перепаковывается в MP4 (mux.js,
  без перекодирования); в настройке попапа можно сохранять TS как есть.
- **DASH** (`js/dash.js`, `js/mp4-merge.js`). В DASH видео и звук — отдельные дорожки.
  Загрузчик берёт видеодорожку выбранного качества и звуковую, строит общий список
  кусков по времени и общий init-сегмент (две дорожки в одном `moov`), а у каждого куска
  при записи меняет только номер дорожки — получается один MP4 со звуком, без
  перекодирования. Куски описываются через `SegmentBase` (индекс `sidx`), `SegmentTemplate`
  или `SegmentList`. Если CDN не принимает заголовок `Range`, куски берутся параметром
  адреса `bytes=` (так работает CDN Одноклассников).

## Структура

```
manifest.json          MV3
background.js          поиск видео, правила заголовков, запуск загрузок, сохранение
popup.html, popup.css  всплывающая панель
offscreen.html         фоновый документ для загрузок
js/popup.js            интерфейс панели
js/offscreen.js        загрузка HLS, DASH и файлов, запись в OPFS
js/hls-download.js     загрузка по сегментам: темп, повторы, запись по порядку (из AnimeLoader)
js/dash.js             разбор DASH-манифеста, список кусков дорожек
js/mp4-merge.js        склейка дорожек fMP4 (видео + звук) в один MP4, разбор sidx
js/playlist.js         разбор m3u8 (m3u8-parser)
js/pacer.js            ограничение темпа запросов
js/output.js           запись файла, TS → MP4 (mux.js)
js/mp4-fix.js          длительность в init-сегменте MP4
js/net-rules.js        запрос правил заголовков у фона
js/sniffer.js          распознавание видео в запросах
lib/                   mux.js 7.1.0, m3u8-parser 7.2.0 (Apache-2.0)
tests/e2e.mjs          сквозной тест в настоящем Chrome
tests/dash-fixture.mjs тестовый DASH для e2e (дорожки из HLS через mux.js)
tests/make-icons.mjs   генератор значков icons/ (npm run icons; --preview <файл.png> — все варианты)
```

## Тест

Локальный сервер изображает сайт с плеером и пускает к плейлистам и сегментам только
с `Referer` страницы; сегменты берутся из публичного тестового потока test-streams.mux.dev.
Тест ставит расширение во временный профиль и дважды скачивает поток через попап
в `Загрузки/VideoLoader` — второй файл должен получить имя с «(1)»; каждый `.mp4`
проверяется по структуре. Кнопка «Открыть папку» проверяется подменой downloads API
(чтобы тест не открывал Проводник), а исчезновение готовых карточек и «Убрать» у ошибки —
по самому попапу. Затем — DASH, устроенный как у Одноклассников (видео одним файлом
с индексом, `Range` отклоняется, куски только через `bytes=`; звук кусками по шаблону):
в попапе должна быть одна строка, а готовый файл — с двумя дорожками. Файлы HLS и DASH
проверяются воспроизведением в Chrome: длительность, кадр, звук, перемотка.

```bash
npm install
npm run e2e
```

## Ограничения

- DRM (Widevine и т. п.) не обходится: такие видео скачать нельзя.
- DASH из нескольких частей (`Period`), трансляции и дорожки WebM пока не поддерживаются.
- HLS-потоки с отдельной аудиодорожкой (аудио в отдельном плейлисте) не поддерживаются.
- Перепаковка TS → MP4 держит видео в памяти (около 150–400 МБ на 20 минут 720p);
  для длинных TS-потоков включите сохранение в `.ts`.
- Во время сохранения файл временно занимает место дважды (OPFS и «Загрузки»).
- Папку вне «Загрузок» расширение выбрать не может: это ограничение downloads API.
- YouTube не поддерживается: дорожки там в WebM, а ссылки устроены по-своему.
- Фильтр рекламы знает только распространённые сети; незнакомый рекламный ролик может
  попасть в список (обычно его видно по размеру или длительности).
